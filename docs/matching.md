# 音源匹配算法速览

四阶段流水线：

```
Stage 1 候选召回（三路搜索 + 分档回退）
  ↓
Stage 2 硬过滤（标题黑名单 + 时长粗筛 ±30s）
  ↓
Stage 3 精确校验（详情接口 + 分P定位，经 enrichTopK 预筛至 6 条）
  ↓
Stage 4 六维加权打分 + 置信度判定
```

## 六维权重

| 维度 | 权重 | 说明 |
|------|------|------|
| 标题歌手匹配 (S1) | 0.30 | 标准格式命中/精确包含得分最高 |
| 时长吻合度 (S2) | 0.30 | 混合分档：小绝对差 + 相对比例 |
| UP主可信度 (S3) | 0.19 | 认证/搬运号加分 + 跨歌学习（trustedUploaderMids） |
| 发布先验 (S4) | 0.06 | 老歌由 UP 主近年搬运是正例信号 |
| 分区与标签 (S5) | 0.08 | 音乐区 + 音乐类标签 |
| 文本规范度 (S6) | 0.07 | 标题去除版本标识后的整洁度 |

## 置信度阈值

| 结果 | 条件 | 行为 |
|------|------|------|
| **AUTO** | ≥ 0.82，或 S1≥0.93 且 S2≥0.80（双硬证据抬升） | 自动激活绑定 |
| **REVIEW** | 0.62 ~ 0.82 | 进人工复核队列；点播场景 ≥ 0.60 的最高分候选也会激活 |
| **无音源** | < 0.62 | 仅留在备选池 |

## 关键设计

- **预筛**（enrichTopK=6）：先用搜索阶段已有字段粗排，只送 Top-K 进详情接口。总请求数从 34 降至 10，单首 ≈68 秒 → ≈20 秒
- **标题黑名单拦截翻唱**：Stage 4 打分层拦不住（翻唱得分 0.686 与真阳性区间重叠），必须靠 Stage 2 的黑名单
- **按需匹配优先**：点播时只匹配当前歌曲，首首可播时间 ≈20 秒，总请求量远低于批量预处理
- **UP 主跨歌学习**：已被验证过的 UP 主 mid 存入 binding 表，后续同 UP 主的候选直接加分
- **负结果缓存**：已确认无音源的歌曲减少重复搜索
